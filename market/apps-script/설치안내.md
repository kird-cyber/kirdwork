# KIRD 나눔마켓 — 구글 시트 + Apps Script 설치 안내

화면(입찰 페이지·관리자 페이지)은 GitHub Pages에 이미 올라가 있습니다.
담당자는 **구글 계정 하나로 저장소(구글 시트)만 만들면** 됩니다. 비용은 들지 않습니다.

- 직원 입찰 화면: https://kird-cyber.github.io/kirdwork/market/
- 관리자 화면: https://kird-cyber.github.io/kirdwork/market/admin.html
- 서버를 연결하기 전에는 **데모 모드**입니다. 입찰 내용은 각자 브라우저에만 저장됩니다.

---

## 1. 구글 시트 만들기 (5분)

1. 구글 드라이브에서 **새 스프레드시트**를 만들고 이름을 `KIRD 나눔마켓`으로 정합니다.
2. 메뉴에서 **확장 프로그램 → Apps Script**를 엽니다.
3. 왼쪽 `Code.gs`의 내용을 모두 지웁니다. 이 폴더의 [`Code.gs`](Code.gs) 내용을 **전부 복사해 붙여 넣고** 저장(💾)합니다.
4. 위쪽 함수 선택 칸에서 `setup`을 고르고 **실행**합니다.
   - 처음 실행하면 「권한 검토」 창이 뜹니다. 내 계정 선택 → **고급 → (안전하지 않음)으로 이동 → 허용**을 누릅니다.
   - 직접 만든 스크립트라서 나오는 정상 안내입니다.
   - 요청하는 권한은 시트 읽기·쓰기, 사진을 저장할 드라이브 폴더 만들기입니다.
5. 아래 **실행 로그**에 `관리자 비밀번호: XXXXXXXXXXXX`가 나옵니다. 따로 적어 두세요.
   - 바꾸려면 **프로젝트 설정(⚙) → 스크립트 속성**에서 `ADMIN_PASSWORD` 값을 고칩니다.

시트에 `설정 · 상품 · 참가코드 · 입찰 · 기록` 탭 5개가 생기고, 드라이브에 `KIRD 나눔마켓 사진` 폴더가 생기면 성공입니다.

## 2. 웹 앱으로 배포 (2분)

1. 오른쪽 위 **배포 → 새 배포**를 누릅니다.
2. 톱니바퀴(유형 선택)에서 **웹 앱**을 고르고 아래처럼 맞춥니다.
   - 설명: `나눔마켓 v1`
   - 다음 사용자 인증 정보로 실행: **나**
   - 액세스 권한이 있는 사용자: **모든 사용자**
     - 직원들이 구글 로그인 없이 입찰하려면 이 값이어야 합니다.
     - 본인 확인은 참가 코드로 합니다.
3. **배포**를 누르고 나오는 **웹 앱 URL**(`https://script.google.com/macros/s/…/exec`)을 복사합니다.
4. 그 URL을 브라우저 주소창에 붙여 넣어 봅니다. `{"ok":true,"service":"kird-market",…}`가 보이면 정상입니다.

## 3. 화면과 연결

복사한 URL을 개발 담당(Claude)에게 전달하면 `market/config.js`에 넣어 바로 배포합니다.
직접 하려면 아래처럼 고치면 됩니다.

```js
window.MARKET_CONFIG = {
  api: 'https://script.google.com/macros/s/…/exec',
  poll: 12000
};
```

연결되면 화면 위쪽의 「데모 모드」 띠가 사라집니다.

## 4. 행사 준비 순서 (관리자 화면)

1. **입찰 규칙·설정**에서 아래 항목을 정하고 저장합니다.
   - 행사 이름, 안내 문구, 시작·마감 시각
   - 경쟁입찰 기준(기본 5만 원), 입찰 단위(기본 100원 — 십원 단위 절사), 입찰 수 표시(기본: 모두)
   - 재입찰 방식
     - 경쟁입찰: 「최고가보다 높게 계속」 또는 「한 번만」
     - 일반입찰: 「금액 바꾸기(낮춰도 됨)」, 「올리기만」, 「한 번만」 중 하나
   - 입찰 취소 허용 여부, 마감 직전 자동 연장, 입찰 인원 표시 여부
2. **상품 관리 → 상품 등록**에서 사진·상품명·최소 입찰가를 넣습니다.
   - 최소가가 기준 금액 이상이면 자동으로 경쟁입찰이 됩니다.
   - 상품마다 경쟁·일반을 따로 지정할 수도 있습니다.
   - 공개 스위치를 끄면 직원 화면에서 숨겨집니다.
3. **참가 코드**에서 인원수만큼 코드를 만듭니다. 이름 목록을 붙여 넣으면 한 줄에 하나씩 만들어집니다.
   - **코드는 만든 직후 한 번만 보입니다.** 바로 「CSV 내려받기」나 「나눠 줄 카드 인쇄」를 해 두세요.
   - 잃어버린 코드는 「재발급」하면 됩니다. 기존 입찰은 그대로 이어집니다.
4. 진행 중에는 **입찰 현황·결과**에서 상품별 1위·2위와 전체 기록을 볼 수 있습니다.
   - 급할 때는 위쪽 「잠시 멈춤」으로 입찰을 막을 수 있습니다.
5. 마감 후에는 아래를 처리합니다.
   - 「결과 CSV」와 「전체 입찰 기록 CSV」를 받아 둡니다.
   - 필요하면 「직원에게 낙찰 여부 보여 주기」를 켭니다.
   - **설정 → 전체 백업(JSON)**을 받아 둡니다.

## 5. 알아 둘 점

- **누가 얼마를 냈는지는 직원 화면 어디에도 나오지 않습니다.**
  - 시트·관리자 화면에서만 「참가자 번호 + 관리자가 적은 메모」로 보입니다.
  - 참가 코드는 알아볼 수 없게 바꿔(해시) 저장하므로, 시트를 열어도 코드 자체는 보이지 않습니다.
- 시트를 손으로 고치면 최대 2분 뒤에 화면에 반영됩니다.
  - 되도록 관리자 화면에서 고치세요.
  - 특히 `입찰` 탭은 손대지 마세요.
- 처리량은 입찰이 한 번에 한 건씩 처리되는 구조라 **초당 1~2건 정도**입니다.
  - 수백 명 규모 사내 행사에는 충분합니다.
  - 마감 직전에 몰리면 몇 초 기다리게 될 수 있습니다. 「마감 직전 자동 연장」을 켜 두면 막판 몰림이 줄어듭니다.
- 사진은 드라이브 폴더에 「링크가 있는 모든 사용자 보기」로 저장됩니다.
  - 기관 구글 워크스페이스 계정에서 외부 공유가 막혀 있다면 사진이 안 보일 수 있습니다. 이 경우 개인 구글 계정으로 설치하세요.
- 코드를 고친 뒤 다시 배포할 때는 **배포 → 배포 관리 → ✏️ 편집 → 버전: 새 버전 → 배포**를 누릅니다. 이렇게 하면 URL이 그대로 유지됩니다.
  - 「새 배포」를 누르면 URL이 바뀌니 주의하세요.
- 행사가 끝나면 백업을 받은 뒤 아래를 정리하세요.
  - 웹 앱 배포를 「보관처리」합니다.
  - 시트의 `참가코드` 탭에 적은 이름 메모를 지웁니다.

## 개발자용

- 규칙과 처리 로직은 `market/assets/core.js` 하나에 있습니다. 브라우저 데모와 Apps Script가 같은 코드를 씁니다.
- 시트 저장소는 `market/apps-script/gas.js`에 있습니다.
- `Code.gs`는 `python3 dev/market/build_gas.py`로 만듭니다. 직접 고치지 마세요.
- 테스트
  - `node dev/market/test.js`: 규칙, 그리고 Apps Script를 흉내 낸 환경에서 `Code.gs`를 그대로 실행
  - `node dev/market/e2e.js`: 브라우저 흐름
